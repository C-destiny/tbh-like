# 符文系统 UI 1.0 实施与交接文档

适用仓库：`tbh-like`

执行对象：WorkBuddy 或后续接手 Agent

目标：把当前“只有文字节点的符文页”升级为可读、可操作、有图标和连线的正式符文树，
同时保持现有 50 个节点的 ID、价格、效果、依赖关系和玩家存档完全不变。

## 1. 当前系统事实

### 1.1 已有能力

- `engine/data/runes.js` 定义 50 个节点：1 个核心节点和 6 条分支链。
- 分支实际为 7 个：核心、成长、财富、便利、宝箱、战斗、经验。
- `engine/rune.js` 已实现依赖检查、扣金币、解锁、加成聚合和最便宜节点查询。
- 玩家存档只保存 `{ runeId: true }`，不保存坐标、图标、价格或效果副本。
- `public/js/app.js` 已能购买节点，但只渲染名称与价格。
- `public/css/style.css` 只有基础的已拥有、可解锁、锁定三种颜色。

### 1.2 当前问题

1. 源文件注释写“8 个方向”，实际只有 7 个分支，且不存在正西分支。
2. 节点没有图标，只能靠逐个读文字理解。
3. 节点之间没有连接线，玩家无法快速看出前置关系。
4. “前置已满足但金币不足”和“现在可以买”使用同一种 `available` 外观。
5. 节点只用浏览器 `title` 显示备注，没有固定详情面板。
6. 分支没有图例、用途说明和完成进度。
7. 画布使用固定坐标，窄窗口主要依赖横向滚动，没有缩放或小屏替代布局。
8. 点击锁定节点仍会发送购买请求，虽然服务器会拒绝，但交互反馈粗糙。

## 2. 本轮锁定范围

本轮只完成符文 UI 1.0：

- 保留全部 rune ID。
- 保留 `requires`、`cost`、`effects` 和聚合算法。
- 不增加符文货币，继续使用金币。
- 不修改存档结构，不递增 `schemaVersion`。
- 不增加新节点，不改变任何战斗或经济数值。
- 增加展示元数据、图标、连接线、详情面板、状态区分和响应式布局。

以下内容必须拆到后续阶段：新增第八分支、把金币改成符文点、重排节点、改价格、改效果、
增加重置/洗点。它们都会改变平衡或存档语义，不得混入本轮提交。

## 3. 目标界面

### 3.1 桌面布局

- 符文画布逻辑尺寸建议为 900×620。
- 核心节点位于画布中心。
- 其余 6 条分支按现有角度向外延伸，节点间距保持一致。
- 依赖线先画，节点后画，避免连接线盖住按钮。
- 画布上方显示：已点亮数量、总数量、当前金币、分支图例。
- 画布右侧或下方设置固定详情面板，显示当前选中节点。
- “最便宜可买节点”保留，但改为推荐区，不替代主树。

### 3.2 小屏布局

宽度低于 720px 时不要强行缩小整棵树：

- 默认改为按分支分组的纵向列表。
- 每个分支可折叠。
- 节点顺序严格按 `ring` 排列。
- 仍显示图标、连接状态、价格和购买按钮。
- 桌面树与移动列表读取同一数据，不复制数值或依赖规则。

### 3.3 节点详情面板

必须显示：

- 图标、名称、分支名称。
- 效果的人类可读描述。
- 金币价格。
- 前置节点名称。
- 当前状态。
- 状态允许时显示“点亮”按钮。
- 失败原因，例如“需先点亮：力量 II”或“金币不足 12,300”。

不要再把 `title` 当作唯一说明渠道；鼠标悬停在触屏设备上不可用。

## 4. 数据设计

### 4.1 分支元数据

在 `engine/data/runes.js` 的 `BRANCHES` 中增加纯展示字段：

```js
south: {
  zh: '成长',
  color: '#4caf50',
  angle: 90,
  icon: 'formation',
  description: '扩充阵容并强化全队生存'
}
```

所有分支都必须具有：

- `zh`
- `color`
- `angle`
- `icon`
- `description`

`branchAngle()` 应读取 `BRANCHES[branch].angle`，禁止再维护第二张角度表。

### 4.2 节点图标键

每个节点增加 `icon` 字段。`chain()` 必须把定义中的 `icon` 复制到生成节点。

图标按效果语义复用，不要求 50 个节点各画一张。建议第一版使用以下 18 个键：

| 图标键 | 用途 | 对应节点示例 |
| --- | --- | --- |
| `core` | 符文树核心 | 战争符文 |
| `formation` | 阵容槽位 | 统帅 I、统帅 II、统御 |
| `skill` | 技能槽位 | 觉醒 |
| `health` | 生命与全队生命 | 生命之树、不灭 |
| `defense` | 防御 | 壁垒、守护 |
| `attack` | 攻击 | 共鸣、力量、战神、终焉之力 |
| `gold` | 金币获取 | 财富 I～V、首领税 |
| `alchemy` | 炼金收益 | 炼金术、点石成金 |
| `crown` | 分支终点 | 贪婪之冠 |
| `bag` | 背包容量 | 行囊 I～III |
| `stash` | 仓库容量 | 收藏页 |
| `auto-chest` | 自动开箱 | 两个自动开箱节点 |
| `timer` | 冷却缩减 | 开箱加速、开箱大师 |
| `chest` | 宝箱掉率与容量 | 探索、征服、囤积、宝库 |
| `rarity` | 稀有度 | 幸运、寻宝者、秘藏、奇迹之匣 |
| `speed` | 攻击速度 | 迅捷 |
| `critical` | 暴击与暴伤 | 暴怒、毁灭 |
| `experience` | 经验与离线成长 | 成长 I～III、训练、安息、冥想、专注、永恒训练 |

图标键是展示元数据，不得参与效果计算。

### 4.3 状态模型

前端必须明确区分四种状态：

| 状态 | 条件 | 视觉 |
| --- | --- | --- |
| `owned` | 已点亮 | 分支色实心、金色外环、勾标记 |
| `affordable` | 前置满足且金币足够 | 明亮分支色、轻微呼吸光、按钮可用 |
| `reachable` | 前置满足但金币不足 | 分支色描边、金币价格为红色、按钮禁用 |
| `locked` | 前置未满足 | 灰度、低透明度、锁标记、按钮禁用 |

颜色不能作为唯一状态信息，必须同时使用勾、锁、亮度或文字标签，照顾色觉差异。

## 5. 图标设计规范

### 5.1 风格

- 与当前 Kenney 像素素材保持一致，采用硬边像素风。
- 源图基准 16×16 或 24×24，运行时显示 32px 或 48px。
- 只允许 nearest-neighbor；CSS 必须设置 `image-rendering: pixelated`。
- 图标应以轮廓识别，不依赖内部小字。
- 禁止在图标内放中文、数字、百分号或价格。

### 5.2 画面约束

- 透明背景。
- 四周至少保留 2px 安全边距。
- 主体占画布约 70%～80%。
- 外轮廓统一使用 1px 深色描边。
- 单图建议不超过 4 个主色，不含状态色。
- 光照方向统一为左上亮、右下暗。
- 同类升级节点复用同一图标，等级通过节点外环和名称区分。

### 5.3 状态着色

原始图标保持中性浅色，不要把分支颜色直接烘焙进 PNG。分支色与状态色由 CSS 外环、底板和光效提供。

- 已点亮：图标原色，外加金色小勾。
- 可购买：图标原色，分支色外环。
- 金币不足：图标降低饱和度，价格红色。
- 未解锁：灰度 100%，透明度约 40%，加锁角标。

### 5.4 资源目录与生成规则

- 原始素材：`assets-src/runes/`。
- 浏览器产物：`public/assets/runes/`。
- 生成脚本：`scripts/prep-rune-assets.cjs`。
- 产物文件名：`rune-<icon-key>.png`，例如 `rune-attack.png`。
- 禁止手工覆盖 `public/assets/runes/`。
- 新素材必须登记进 `assets/LICENSES.md`；如果完全自行绘制，注明“项目自有素材”。
- 若使用 Kenney，只选实际需要的源文件入 Git，不提交整个素材包。

### 5.5 图标验收

图标必须在以下尺寸分别检查：16px、32px、48px。验收重点：

- 32px 时不看文字也能区分攻击、防御、生命、金币、宝箱和经验。
- 灰度状态下仍能靠轮廓区分。
- 深色面板上没有黑边消失或发灰的半透明插值。
- 图标之间不存在描边粗细、光照方向和像素倍率混用。
- 不得出现 Emoji、真实品牌 Logo 或来源不明素材。

## 6. 文件级实施清单

### 6.1 `engine/data/runes.js`

- 修正文档中的“8 个方向”为实际 7 个分支。
- 给 `BRANCHES` 增加 `angle`、`icon`、`description`。
- 给每个节点定义增加 `icon`。
- `chain()` 把 `icon` 复制到节点。
- `branchAngle()` 改为读取 `BRANCHES`，或在无调用后删除。
- 不改 ID、价格、效果和依赖。

### 6.2 `engine/rune.js`

- 保持 `aggregate()`、`canUnlock()` 和 `unlock()` 行为不变。
- `treeView()` 可增加 `reason` 和 `affordable` 展示字段，但不得把购买判定复制成另一套规则。
- 如果新增展示字段，优先复用 `canUnlock()` 或抽取纯判定函数。

### 6.3 `public/js/rune-ui.js`

新增专用渲染模块，避免继续膨胀 `app.js`。职责：

- 计算节点坐标。
- 生成 SVG 连接线。
- 渲染节点图标与四种状态。
- 管理当前选中节点。
- 渲染详情面板和购买按钮。
- 提供桌面树与小屏列表两套视图。

禁止在该文件定义价格、效果数值和依赖关系。

### 6.4 `public/js/app.js`

- `tabRunes()` 只准备容器和摘要数据。
- 将实际树渲染委托给 `RuneUI.render(...)`。
- 购买成功收到新快照后重新渲染，不做乐观写入。
- 保留服务器权威的 `App.act('buyRune', { runeId })`。

### 6.5 `public/css/style.css`

- 新增画布、连线、分支图例、图标、状态角标和详情面板样式。
- 所有节点必须有 `:focus-visible` 样式。
- 触控目标不得小于 44×44px。
- 动画遵守 `prefers-reduced-motion`，关闭呼吸和闪光动画。
- 小于 720px 切到分支列表布局。

### 6.6 `scripts/ui-smoke.cjs`

至少增加以下断言：

1. 50 个节点 ID 无重复。
2. 每个节点有存在的分支和图标键。
3. 每个非核心节点的 `requires` 都指向真实节点。
4. 每条分支首节点依赖 `war_1`。
5. 四种 UI 状态能够被构造。
6. 18 张图标产物全部存在。
7. 连接线数量等于全部依赖边数量。
8. 锁定或金币不足节点不生成可用购买按钮。

### 6.7 `scripts/smoke.cjs`

保持原有购买用例，并补充：

- 重复购买失败且不二次扣金币。
- 跳过前置节点购买失败。
- 金币不足失败且余额不变。
- 点亮节点后对应加成只出现一次。
- 旧存档中已有 rune ID 仍能正常聚合。

## 9. 浏览器验收清单

- 桌面宽度下整棵树中心明确，节点不互相覆盖。
- 所有依赖线准确连接父子节点。
- 核心未点亮时，其余分支全部锁定。
- 核心点亮后，各分支第一节点进入可达状态。
- 金币不足与可以买的状态明显不同。
- 点击节点先选中并展示详情，不直接误购买。
- 购买必须通过明确按钮完成。
- 购买成功后节点、连线、金币和推荐区同步更新。
- 720px 以下自动切到分支列表，不出现横向页面溢出。
- 键盘 Tab 可以选中节点并操作购买。
- 开启系统“减少动态效果”后不播放呼吸动画。
- 刷新、断线重连和换电脑后已点亮状态保持一致。

## 10. 禁止事项

- 禁止改变任何既有 rune ID。
- 禁止把符文效果写进 `public/`。
- 禁止前端自行扣金币或写入已拥有状态。
- 禁止在 UI 提交里修改价格、效果或怪物/装备数值。
- 禁止引入前端框架或第二套状态管理。
- 禁止使用 Emoji 代替符文图标。
- 禁止提交完整 Kenney 素材包、缓存、临时截图或运行数据。
- 禁止跳过 `AGENTS.md`、`HANDOFF.md` 和阶段提交要求。
